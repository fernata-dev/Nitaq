## ١) الليلة: جهّز اللاب توب (CachyOS) — ٢٠ دقيقة

> إنت شغّال على **fish shell** (باين من الـ prompt). عشان كده `source .venv/bin/activate` بايظ عندك:
> الملف ده مكتوب لـ bash. استخدم `activate.fish`. ودي الأوامر الكاملة للـ fish:

```fish
# لو فولدر Nitaq موجود من قبل، ادخله على طول (متعملش clone تاني):
cd ~/Nitaq ; or git clone https://github.com/fernata-dev/Nitaq.git ~/Nitaq ; and cd ~/Nitaq
python -m venv .venv
source .venv/bin/activate.fish        # ← مهم: .fish مش activate لوحده
pip install -e ".[dev]"
python -m nitaq_bench restore-tags          # يرجّع علامات المراحل (m1 … m20)
python -m pytest                      # كل الاختبارات لازم تعدّي
python tools/demo/meeting_demo.py     # الديمو كله، خطوة خطوة (Enter بين كل خطوة)
python -m nitaq_bench report ; and xdg-open report/index.html
python -m nitaq ui                   # التطبيق في المتصفح
```

**ملاحظات على الأخطاء اللي ظهرتلك في الـ terminal:**
- `'nitaq' (0.3.0) already seems to be installed` — عندك نسخة قديمة متثبّتة بـ pipx. مش محتاجها
  خالص للديمو (الديمو بيشتغل من الـ venv جوه فولدر Nitaq). لو عايز تحدّثها: `pipx upgrade nitaq`
  أو `pipx install --force "git+https://github.com/fernata-dev/Nitaq.git"`.
- `No module named nitaq_bench` و `can't open file '.../tools/demo/meeting_demo.py'` — سببهم إن الـ venv
  ماكانش متفعّل (مشكلة fish فوق) وإنك ماكنتش جوه فولدر Nitaq. الأوامر اللي فوق بتحل الاتنين.

لو الريبو خاص وطلب منك باسورد: `gh auth login` الأول، أو حمّله ZIP من GitHub.

**خطة بديلة لو النت أو أي حاجة وقعت:** فيديو العرض الكامل `demo/Nitaq_Full_Demo.mp4` (الـ terminal
والتطبيق، ونص الشرح في `demo/SCRIPT.md`)، والصور في `docs/media/` (`docs/media/site/` = الموقع).
حطهم على الفلاشة كمان.

| ٢ دقيقة | الحدود واللي جاي | `docs/LIMITATIONS.md` |

**الديمو بيعرض إيه** (اشرح كل خطوة بكلامك):
1. نِطاق بيلاقي إعدادات Claude Code وGemini CLI والمهارات وسيرفرات MCP — قراية بس، على home وهمي.
2. نفس الهجوم بالإنجليزي والمصري والفرانكو وBase64: فاحص النصوص (D2) لقط بعضهم، ونِطاق رفض الأربعة لأنه بيبص على الفعل نفسه (إيميل رايح لـ attacker@test.local). قول إنه «مثال واحد».
3. الوسيط: صفحة عادية اتمنعت في الوضع الصارم (ده تمنه)، والإرسال للمهاجم اتمنع، وقراية ~/.ssh اتمنعت، والأداة المسمومة استخبت.
4. الوضع الذكي: الصفحة اتسمحت، والعنوان اللي ظهر جواها اتمنع.
5. فحص ملف مهارة مسموم من غير ما يتنفّذ.
6. معاينة الحماية: بيوريك الـ diff بالظبط قبل أي تغيير.

## ٣) أسئلة متوقعة — وإجابات أمينة

**«هل بيمنع أي جيلبريك؟»**
لأ، ومفيش حاجة تقدر تضمن ده: الموديل ممكن يتخدع بصياغة محدش شافها قبل كده. اللي نِطاق بيعمله
مختلف: حتى لو الجيلبريك نجح، الفعل الممنوع (إرسال لعنوان مش مسموح، قراية ملف سري، أداة مسمومة)
بيتقفل في الأماكن اللي نِطاق واقف عليها، لأنه مبيقراش الكلام أصلًا.
الجملة الرسمية: «نِطاق بيقلّل الضرر اللي ممكن تعمله تعليمة محقونة؛ مش بيمنع الموديل إنه يتبعها.»

**«جرّبته على موديل حقيقي؟»**
لسه. التجربة على موديل حقيقي (pilot) جاهزة كأوامر بس ماتشغّلتش (`results/pilot_status.json`).
الأرقام الحالية من محاكي «أسوأ حالة» بيطيع أي أمر. الخطوة الجاية: أشغّلها على جهازي (README، قسم pilot).

**«مين كتب الهجمات؟»**
الموجود دلوقتي مسودات من الذكاء الاصطناعي، بحد أقصى ٥ لكل لغة، ومتعلّم عليها `ai-draft`.
الهجمات الحقيقية بالمصري والفرانكو هكتبها أنا في `data/attacks/student_written/`.

**«استخدمت ذكاء اصطناعي؟»**
أيوه، والكود كله مكتوب بيه، ومذكور بالتفصيل في `docs/AI_PROVENANCE.md`، وكل الأوامر اللي
اتكتبت له في `docs/prompt_log.md`. اللي عليا: البيانات، والتجربة على موديل حقيقي، والتفسير.

**«إيه الجديد؟»** متقولش «أول مرة في العالم». قول اللي بتعمله: بتقيس الحقن بالمصري والفرانكو
والتشفير، وبتقارن فلتر بيقرا الكلام بضابط صلاحيات مبيقراش الكلام.

**«إيه اللي مش بيغطيه؟»** أدوات المساعد اللي من غير وسيط أو hook (زي terminal جوه Antigravity)،
وسيرفرات MCP البعيدة، والتلاعب جوه المسموح، والعناوين اللي بتتركّب من أجزاء. (`docs/LIMITATIONS.md`)
